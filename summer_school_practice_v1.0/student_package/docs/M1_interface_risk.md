# M1-2 接口、通信与风险说明

## 1 原始接口提供什么数据？
TeachingLink 是本课程自定义的教学协议，不对应 ASTERIX、ADS-B/Mode-S、Link 16 或任何行业标准与企业装备协议。一帧仅承载一条位置状态消息。

## 2 为什么原始数据不是完整态势结果？
raw_states.json 是 OpenSky 接口获取的离线状态向量快照，它不是完整的当前态势表。原因在于：原始数据中存在空值和可空字段，同一个目标可能有多个时刻的记录；必须经过发送方封装、接收方解码、按目标分组、按时间排序并提取最新状态后，才能形成反映目标当前情况的“当前态势表”。

## 3 为什么发送方需要把内部状态封装成消息？
将浮点数和字符串转换为固定字节序（大端）、固定位宽的无符号整数，通过比例因子和偏置完成定点编码。这保证了不同系统间数据的精确定义。

## 4 为什么接收方要检查长度、类型、校验和与保留位？
通过 Magic(0x4453)、长度(41字节)、Checksum(前39字节之和模65536) 以及保留位检查，确保数据在模拟传输中未被损坏且格式合规。

## 5 CSV 与 SQLite 分别承担什么角色？
CSV：作为主要的中间数据和最终成果持久化格式，便于人工阅读和跨工具验证。
SQLite：作为选做持久化方案，便于对多时刻航迹记录进行高效查询、按时间或目标快速检索。

## 6 工程风险说明
在本数据链处理链中，存在以下三个主要工程风险：

1、字段缺失与空值混淆风险：有效位为0表示字段缺失。若接收端不先读取有效位，直接把占位整数 0 解释为物理量（如纬度0度或高度0米），将导致严重的态势判读错误。
2、量化误差与越界风险：连续小数编码为有限位宽整数会产生量化误差；若发送端在编码前不检查量程，而是通过截断或取模静默处理越界值，将导致数据严重失真且难以察觉。
3、字节序与保留位异常风险：若未严格按照网络字节序（大端）解析，或经纬度3字节容器最高2位及标志字节保留位不为0时未触发异常，将导致整体数据解析错位或隐藏协议破坏。
